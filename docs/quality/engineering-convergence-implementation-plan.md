## POM 与分层边界

- **System Brain** 保存页面身份、路由、定位点、页面控件证据、快照版本和确认状态。
- **POM** 在当前浏览器会话中解析已确认页面和控件，执行填值、点击、选择和状态读取；定位歧义、页面变化或知识过期时停止并请求探索/复核，不退回未确认选择器。
- **Testcase Brain/Harness** 决定流程顺序、角色交接、实体引用、写入前后核对和中断恢复。POM 不决定审批路线、重试业务写入或测试数据生命周期。
- **Oracle** 保存预期值、适用条件和业务实体引用；目标系统独立后置状态用于确认业务结果。
- 复杂控件可以通过业务工作区明确登记的扩展实现，扩展不得把客户业务规则带入通用产品。

当前 MCP 拆分模块为：`src/mcp/handlers.ts`、`src/mcp/requirementWorkflowHandlers.ts`、`src/mcp/facadeProjectionHandlers.ts`、`src/mcp/handlerArguments.ts` 和 `src/execution/hostPlaywrightRunner.ts`。模块文件本身仍有进一步分层空间，后续按可独立测试的服务逐步拆分。

## 指标和报告规则

- **实现完成度**：正式通过的旧 A–F 交付包数，按 `N/6` 报告；代码已存在不代表通过。
- **真实业务完成度**：有有效独立业务证据的场景数／固定场景总数。
- **自主完成度**：无需额外人工操作或源码修补完成的场景数／同一固定总数。首次授权/登录单独记录。
- blocked、失败、未执行必须保留在真实业务与自主完成分母；synthetic（合成）独立列出。
- 缺少符合口径的实测数据时，指标显示“未测量”，不填零、不估算、不记通过。
- 恢复测试要核对目标后置状态，不因响应丢失自动重放写操作。

## PR 审查流程

日常开发只使用本地 `fixture`：`origin/main` → `fixture`。每批工程任务通过准出检查后推送 `fixture` 并建立审查 PR，附具体变更、失败反例、测试结果、风险和验收报告。用户审阅 PR 并明确批准具体 head SHA 后，才允许本地 `main` 快进合并并推送 GitHub `main`。

PR 内容变化后须按新 SHA 重新审查。快进失败、分支保护拒绝、未审查提交或检查未通过时停止；不强推、不重置、不绕过 PR 自动更新远端 `main`。不自动发布 npm。
