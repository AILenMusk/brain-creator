## 1. 本次验收要回答的问题

验收重点是判断已提交的 A–F 实施内容是否满足各自的交付条件，并说明哪些结论只由合成测试支持、哪些已经在真实业务系统验证。以下三件事必须分开报告：

1. **候选实现有工程证据**：某一准确 commit 上的代码审查、反例测试和集成检查通过。
2. **交付包正式验收**：候选证据齐全，代码合入选定基线，并通过合入后的身份和安装冒烟检查。
3. **真实业务场景通过**：在授权系统中执行，且由独立的目标系统后置状态和有效证据证明符合已批准 Oracle。

代码存在、单测通过、CI 绿色、PR 合入、浏览器夹具通过都不能单独替代另外两种结论。

## 3. 验收结论和计数口径

### 包级结论

每个交付包只用以下状态：

| 状态 | 含义 | 是否计入 `N/6` |
| --- | --- | --- |
| 候选工程通过 | 准确候选 commit 的必要反例、回归和工程门禁通过，但尚未合入基线 | 否 |
| 正式验收通过 | 包级门槛通过、证据归档、合入选定基线，且合入后冒烟通过 | 是 |
| 部分通过 | 有实现和部分证据，仍有包级必需条件未满足 | 否 |
| 未通过 | 必需反例失败、存在错误成功，或结论无法绑定到运行版本 | 否 |
| 阻塞 | 缺外部环境、权限、鉴权、目标查询或其他前置条件 | 否 |
| 未测量 | 没有实际样本，不能计算或判断 | 否 |

**实现完成度**只按正式验收通过的包数计为 `N/6`。未合入的候选实现可以报告为“候选工程通过”，不能折算成正式通过或百分比。

### 场景级结论

- **真实业务完成度** = 有独立、有效业务后置证据且符合已批准 Oracle 的场景数 / 冻结的全部选定场景数。
- **自主完成度** = 无初次授权/登录以外的额外人工操作且真实通过的场景数 / 同一冻结分母。
- blocked、失败、未执行场景必须保留在分母；不因运行困难或无第二系统而删除。
- 初次授权和登录单独计数；每次后续人工介入记录次数、原因、发生步骤和是否可恢复。
- Trial 不存在或样本不足时，真实业务完成度、自主完成度、恢复率、清理率及基线变化均显示“未测量”，不显示 0% 或通过。
- synthetic 结果独立列示，不进入真实业务指标、Trial 晋升或无人值守资格。

## 4. 验收证据链

每条实施声明必须建立一条可复核记录：

> 计划要求 → 代码位置/关键行为 → 正向测试 → 失败反例 → 准确 commit/build → 命令或 CI 结果 → 产物位置 → 验收结论

验收时按以下顺序执行：

1. **冻结版本和范围**：记录主线与候选 SHA、PR、依赖锁文件、Store schema、包版本、构建标识、MCP PID/启动时间、workspace、Provider，以及需求/系统/场景/Oracle 的 revision 或 hash。变化即创建新验证记录，不覆盖旧记录。
2. **先审失败反例**：证明错误输入和不完整证据不能产生“强通过”“conform”或可信晋升。反例失败即停止对应包的通过判定。
3. **审查实现声明**：代码路径与产品要求一一对应；只看文件存在、测试名称或 mock 调用不构成证据。
4. **运行包级和集成检查**：所有结果绑定到准确 commit。代码变化后重跑受影响测试和完整候选检查；旧 commit 的绿灯不能替代新 commit 检查。
5. **独立复核与归档**：复核人依据命令输出、CI 链接、日志、报告和产物可重现结论。浏览器夹具明确标注 synthetic。
6. **合入后正式判定**：只有合入选定基线并完成合入后身份、安装和宿主冒烟，包才计入 `N/6`。
7. **另行运行真实 Trial**：只有真实 Trial 前置条件全部满足才执行业务写入，并用目标系统独立查询验证结果。

## 7. 真实 Trial 准入条件

任一条件缺失，保持阻塞，不开始写入：

1. 本轮需求主文档及全部选定子文档 revision/hash 已确认；草稿附件分析不自动构成 Oracle。
2. 每个场景的起止状态、角色交接、前置条件、分支、业务对象、数据计划、系统绑定和可判定 Oracle 已由人工审核并冻结。
3. 场景分母固定。Test5 本地 GHR 场景与 Beisen 跨系统需求分列；Beisen 在第二真实系统与单独授权就绪前保留为 blocked，不能从分母排除。
4. 当前登录状态、目标路由和执行账号角色经过当轮核验；用户授权边界与系统实际权限证据分别记录。
5. 独立目标系统后置查询和 TestData provider 指向正确系统、可以读取真实业务状态；不是从执行器返回值或同一份截图推断成功。
6. 每轮绑定 Trial ID、需求/场景/Oracle hash、代码/build identity、system/knowledge project、角色断言和产物。源码修补、需求变化、绑定变化或场景变化时开启新验证记录。
7. 创建、提交、转交、审批、关闭只在既有授权范围执行；清理前提前通知并记录确认。批准保留的数据记录保留原因和标签。

每轮恢复前先查目标系统。如果目标动作已生效，记录对账结果并跳过重放；只有确认未生效才可按同一任务恢复。三轮 Trial 使用独立运行记录，旧截图和旧 Trial 不能填补当前轮证据。
